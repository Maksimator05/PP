# Retail Category Weekly Forecast

Учебный проект по дисциплине «Проектный практикум», вариант 3: прогноз недельных продаж по товарным категориям розничной сети. Система показывает, как перейти от открытых данных и текстовых описаний промо к проверенному прогнозу, хранилищу, мониторингу и дашборду.

## Источники и режимы данных

- `DATA_SOURCE=x5` - режим открытого X5 RetailHero. Поддерживаются опубликованные `purchases.csv.gz` и `products.csv.gz` внутри вложенной папки `data/`, а также CSV, CSV.GZ и Parquet транзакции, положенные в `data/raw/x5_retailhero/`. Покупки объединяются со справочником товаров, чтобы получить категорию. Для строк продаж используются продуктовые суммы `trn_sum_from_iss` и `trn_sum_from_red`, если они есть; если нет, сумма чека `purchase_sum` распределяется между товарами по их количеству.
- `DATA_SOURCE=synthetic` - детерминированный автономный пример. Создаются отдельные транзакционные и слабоструктурированные промо-данные. Они явно маркируются как синтетические и не выдаются за реальные продажи X5. В этом режиме сеть не используется.

Реальный X5 RetailHero содержит крупный файл истории покупок. Загрузка таких файлов требует достаточно свободной памяти; автономная демонстрация использует компактный синтетический набор.

## Быстрый старт

Скопируйте файл настроек и запустите локальный сценарий:

```powershell
Copy-Item .env.example .env
python -m pip install -r requirements.txt
python scripts/run_demo.py --local
pytest -q
```

Для ручного запуска без `make` эти команды подходят и в PowerShell, и в обычном терминале. Результаты сохраняются в `data/processed/`, `artifacts/` и `models/`.

## Что делает система

1. Находит открытый источник или формирует явный синтетический fallback.
2. Приводит даты, магазины, товары и категории к канонической схеме; сохраняет исходные файлы отдельно.
3. Проверяет обязательные значения, даты, повторные строки, отрицательные суммы и количества, аномалии.
4. Формирует недельную витрину продаж по магазину и товарной категории.
5. Строит лаговые, оконные, календарные и текстовые признаки. Признаки используют только информацию, доступную к моменту прогноза; целевая неделя всегда позже даты отсечения.
6. Сравнивает сезонный наивный прогноз, Ridge, градиентный бустинг и Random Forest. Параметры задаются в конфигурации.
7. Выбирает модель по WAPE на validation-периоде, повторно обучает ее на train и validation и только после этого оценивает на отложенном финальном тесте.
8. Строит рекурсивный прогноз на 1–4 недели, рассчитывает MAE, RMSE, WAPE и sMAPE.
9. Сохраняет важность признаков двумя способами, зависимость прогноза от ведущих признаков, локальное аддитивное объяснение одного прогноза и отчеты PSI.
10. Показывает историю, прогноз, метрики, качество данных, мониторинг и объяснения в Streamlit.

## Команды

- `python scripts/download_x5_dataset.py --force` - попытаться получить публичный X5-набор.
- `python scripts/verify_x5_dataset.py` - проверить, что файл транзакций найден и распознается.
- `python scripts/inspect_x5_dataset.py` - построить профиль локального набора.
- `python scripts/run_demo.py --local` - полный SQLite-сценарий.
- `python scripts/build_project_report.py` - пересобрать подробный Word-отчет из последних артефактов демо.
- `make demo` - запустить PostgreSQL в Docker Compose и выполнить ETL и обучение из локального Python-окружения.
- `docker compose --profile full up --build` - поднять PostgreSQL, приложение и дашборд в Docker.
- `python scripts/db_counts.py --database-url postgresql+psycopg2://retail:retail@localhost:5432/retail_forecast` - проверить число строк в PostgreSQL.
- `make test` или `pytest -q` - выполнить автоматические проверки.
- `make prefect-all` - выполнить локальный именованный flow; если установлен Prefect, применяется его декоратор flow.
- `make dashboard` - открыть дашборд после подготовки данных.

## Архитектура

Исходные файлы хранятся в `data/raw/`; транзакции проходят канонизацию и контроль качества; недельные факты, промо-тексты, календарь, признаки, прогнозы и метрики сохраняются в PostgreSQL либо локальном SQLite. SQL-схема расположена в `sql/001_schema.sql`. Загрузка фактов выполняется через upsert по первичным ключам: повторный прогон не создает повторные транзакции и недели, а уже существующие ключи обновляются.

В коде подготовлены SQLite и PostgreSQL режимы, таблицы журналов ETL и проблем качества, логика инкрементального состояния и мониторинг дрейфа. Для самостоятельного подтверждения PostgreSQL пути используйте команды проверки ниже: Docker в среде разработки не запускался.

## Структура проекта

```text
config/                 параметры проекта и маппинг X5
dashboard/              интерактивное приложение Streamlit
docs/                   архитектура, словари, ограничения и матрица требований
retail_forecast/        загрузка, качество, признаки, модели, прогноз, мониторинг
scripts/                команды запуска и проверки
sql/                    схема хранилища
tests/                  проверки загрузчика, ETL, признаков и моделей
data/raw/               исходные и синтетические данные (игнорируются Git)
data/processed/         обработанные данные (игнорируются Git)
artifacts/              метрики, объяснения и мониторинг (игнорируются Git)
models/                 сериализованные модели (игнорируются Git)
output/                 отчет Word
```

## Самостоятельная проверка Docker/PostgreSQL

Docker не требуется для локальной демонстрации, однако следующим шагом можно проверить PostgreSQL-путь:

```powershell
docker compose --profile core up -d
python scripts/run_demo.py --database-url postgresql+psycopg2://retail:retail@localhost:5432/retail_forecast
python scripts/db_counts.py --database-url postgresql+psycopg2://retail:retail@localhost:5432/retail_forecast
docker compose --profile core ps
```

Ожидаемый результат: PostgreSQL находится в состоянии `healthy`; скрипт демо печатает `is_synthetic`, выбранную модель и оценки; в счетчиках `sales_raw`, `feature_store`, `forecasts`, `metrics` и `etl_logs` есть строки. Для полного интерфейса выполните `docker compose --profile full up --build`, затем откройте `http://localhost:8501`.
