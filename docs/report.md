# Отчет по проекту

## Постановка задачи

Нужно прогнозировать недельную сумму продаж `sales_amount` по категориям розничной сети. Пользователь прогноза - категорийный менеджер, который принимает решения о запасах, промо и планировании выручки.

## Данные

Основной источник - X5 RetailHero из публичных источников. Проект поддерживает HuggingFace `pytorch-lifestream/retailhero-uplift`, Kaggle при наличии ключей и явный синтетический fallback. Второй источник - слабоструктурированные промо-тексты, которые преобразуются в числовые признаки: длина текста, число слов, скидка, признаки bundle, новинки, распродажи и словарная тональность.

## ETL и хранение

Сырые файлы сохраняются в `data/raw`. Обработанные артефакты пишутся в `data/processed`; для полноценного запуска предусмотрен PostgreSQL и схема `sql/001_schema.sql`. В схеме есть уникальные ключи, ограничения неотрицательности продаж, таблицы прогнозов, метрик, логов и проблем качества.

## Качество данных

Проверяются обязательные поля, даты, дубли транзакций, отрицательные продажи и пропуски. Отклоненные записи сохраняются в `transactions_rejected.csv` и могут быть загружены в `data_quality_issues`.

## Признаки и защита от утечки

Признаки строятся только из прошлого: лаги `1, 2, 3, 4, 8, 12`, rolling mean/std со сдвигом на одну неделю, календарные признаки целевой недели и промо-признаки. Автоматическая проверка требует `as_of_date < target_week`.

## Валидация

Используется временной split: финальные недели идут в тест, случайного разбиения нет. Для расширенной проверки реализованы rolling splits с эмбарго.

## Модели

Реализованы минимум три класса моделей:

- `seasonal_naive`: сезонная наивная модель по лагу.
- `ridge`: линейная модель со стандартизацией.
- `catboost_or_histgb`: CatBoost при наличии зависимости или sklearn HistGradientBoosting fallback.
- Дополнительно есть RandomForest как запасная нелинейная модель.

## Метрики

Считаются MAE, RMSE, WAPE и sMAPE. WAPE переводится в бизнес-термины как доля недельной выручки, которую менеджер рискует недо- или переоценить.

## Интерпретация и мониторинг

Для интерпретации используются feature importance моделей, а при установке SHAP можно добавить SHAP-графики без изменения интерфейса. Мониторинг включает PSI по признакам и метрики качества прогнозов.

## Результаты локального запуска

В текущей среде публичные источники недоступны, поэтому использован синтетический fallback. `make demo` создал 15967 транзакций, 3840 недельных агрегатов, 3808 строк признаков. Лучшая модель локального запуска - `ridge`, WAPE около 39.6%.

## Ограничения

Синтетический fallback нужен только для демонстрации инженерного контура. Для защиты с реальными данными следует один раз скачать X5 RetailHero, проверить профиль датасета и переобучить модели.
